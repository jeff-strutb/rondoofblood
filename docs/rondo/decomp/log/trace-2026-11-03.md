# Tracing, 2026-11-03

## Hooks (core patch 0003)

- `RdMem` reports every read with its physical address and kind (data,
  operand, opcode: the loop's fetch now goes through `RdOpcode`); `WrMem`
  and `WrMemPhysical` every write; the reset and interrupt entries a
  hook of their own.
- scsicd.cpp keeps, beside each of the data FIFO's 2,048 bytes, the
  absolute disc byte it came from (sector reads) or none (sense and other
  simple data); the byte popped onto DB takes its origin, every other
  assignment to DB clears it. pcecd.cpp records DB's origin when the CPU
  reads $1801 or $1808 (`rondo_cd_origin`).
- Core rebuilt clean: SHA-1 prefix `8b36cd67b0d0`.

## The fold (pcebox `--trace`, trace.c)

Per physical RAM byte (Super RAM $68-$7F, CD RAM $80-$87, base RAM $F8
with its mirrors), its disc origin. Data flow per opcode class, generated
from huc.py (`--c-opclass`). Executed bytes are credited to the disc
through the origin; System Card bytes ($00-$1F) to a map of the card; RAM
with no origin to a map of the physical space.

Checks, boot script: at frames 120, 126, 180, 240, 480 and 900, 0, 2,604,
85,478, 165,349, 261,524 and 261,165 RAM bytes hold an origin, 0 differ
from the disc. With `--plant-origin 1`: 0, 1,336, 54,072, 123,274,
223,344 and 223,418 differ. The core's LBA and this tree's agree (user
sector 0 = LBA 3,890): no byte differs.

## Frames

`WANT_16BPP` and draws RGB565 after the frontend refuses it. pcebox now
takes RGB565 and converts. The traces did not change (7,533 B attract).

## The menus

RUN at the title (frame 6,826) was ignored: the title is up by frame
7,300. On the file menu I, RUN and II did nothing. A dump around a held
I showed $2228-$222C (all five pad slots, no multitap) set to $01 and
$2232 following a frame later: the press arrives. `--watch` on $222D
found the game's readers in the overlay from sectors $C1-$C4 (bank $6B);
$9C4B takes I only if the bit for the cursor ($34B8, 1) is set in $26D3
($10: only item 4). DOWN steps the cursor 1, 2, 3, 4, 5. Two scripted
paths then went wrong (a count off after END, twice) before the path in
`_newgame.txt`, its file-menu cursor checked at 1 from a dump.
